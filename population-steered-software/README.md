# Population-Steered Software

A real user population qualifies what gets written next. An agent writes the candidates. Humans hold only the boundaries: consent, money, keys, private data, and protocol compatibility.

The loop is a funnel, not a pile of work:

```
capture → qualify → candidate → validate → promote
```

Most signals die at qualification. That is the design.

“Living software” already names runtime agency (one person, one session, one adapting instance). This is a selection architecture for *shared source*.
